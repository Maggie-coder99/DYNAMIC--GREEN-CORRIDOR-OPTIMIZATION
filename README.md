# Dynamic Green Corridor Optimization for Ambulance

**Pulse Corridor** is a college / portfolio web application that **simulates** emergency dispatch, traffic-aware route scoring, and a moving green corridor of traffic signals.

> This project is an academic software simulation and does not directly control real-world traffic infrastructure. Traffic conditions, ambulance movement, and traffic signal behavior are simulated unless connected to authorized real-world infrastructure.

## Problem statement

Ambulances lose minutes at congested intersections. Municipal “green corridors” are hard to demonstrate in software without hardware. This prototype shows how a control room could choose a **better** route (not merely the shortest) and **sequence** signal priority as the vehicle moves.

## Objectives

- Dispatch an ambulance to a hospital on an interactive map
- Score routes using distance, travel time, density, and signal delay
- Simulate traffic that changes during the trip
- Activate a limited, sequential green corridor
- Recalculate when congestion appears
- Record ETA, time saved, history, and analytics

## Features

- Role-based demo login (operator, traffic control, admin)
- Emergency dashboard with KPIs and live map
- Ambulance / hospital / signal management views
- Leaflet map (CARTO dark tiles; optional Mapbox token)
- Route optimizer module
- Green-corridor lookahead
- Timer-based ambulance motion
- Toasts for corridor, clearance, congestion, alternatives
- Recharts analytics and searchable trip history
- Works fully in **demo mode** on a laptop

## Technology stack

| Layer | Choice |
| --- | --- |
| Frontend | React 18, Vite, Tailwind CSS, React Router, Lucide, Recharts, Leaflet |
| Backend | Node.js, Express, JWT, Zod, Helmet, CORS, rate limit |
| Data | PostgreSQL schema + seeded in-memory store for zero-config demo |
| Maps | OpenStreetMap / CARTO (no key). Mapbox if `VITE_MAPBOX_TOKEN` is set |

Leaflet + CARTO is used instead of requiring a Mapbox/Google billing key so the project remains demonstrable. Tokens, when used, stay in environment variables and are never hardcoded.

## Installation

```bash
git clone <repo>
cd DYNAMIC--GREEN-CORRIDOR-OPTIMIZATION
cp .env.example .env
npm install
```

## Environment variables

See `.env.example`. Important:

- `PORT` — API port (4000)
- `FRONTEND_ORIGIN` — CORS origin
- `JWT_SECRET` — change in any shared deployment
- `VITE_API_URL` — leave empty in local Vite (proxy) or set to the deployed API
- `VITE_MAPBOX_TOKEN` — optional public map token
- `DATABASE_URL` — reserved for a future Postgres adapter

## Database setup

Demo: nothing to install. Optional Postgres:

```bash
psql "$DATABASE_URL" -f database/schema/schema.sql
psql "$DATABASE_URL" -f database/seed/seed.sql
```

## Deployment

**Frontend (Vercel)**  
Root `frontend`, build `npm run build`, output `dist`. Set `VITE_API_URL` to the public API origin **before** build.

**Backend (Render / Railway)**  
Root `backend`, start `npm start`, Node 20+. Set `PORT`, `JWT_SECRET`, `FRONTEND_ORIGIN`.

**Database (Supabase)**  
Run `database/schema/schema.sql` then seed. Wire `DATABASE_URL` once a Postgres adapter is added.
